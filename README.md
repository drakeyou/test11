# gg.bet CS2 live monitor

Монитор лайв-счёта и коэффициентов по Counter-Strike на gg.bet.

Данные берутся из **сетевых ответов самого сайта** (XHR + WebSocket), а не из
вёрстки. Селекторы ломаются при каждом редизайне — API-ответы живут дольше.

## Требования

- Node.js 20+
- Регион, из которого gg.bet открывается. Сайт отдаёт `403 This internet site is
  not accepting visitors from your region` для заблокированных стран — это
  происходит на уровне Cloudflare, до загрузки JS, и никаким кодом не решается.
  Если нужен прокси, передайте его флагом `--proxy` (см. ниже).

## Установка

```bash
npm install
npx playwright install chromium
```

## Использование

### 1. Discovery — снять сырые ответы

```bash
npm run discover
```

Открывает лайв-раздел, 60 секунд пишет все JSON-ответы в `captures/` и печатает
по каждому строку вида:

```
[xhr] 0007-xhr.json  18422b  matches:6  https://gg.bet/api/.../live
[ws]  0011-ws.json     964b  matches:1  wss://.../socket
```

Колонка `matches:` показывает, сколько матчей вытащил парсер из этого ответа.
Дальше эти файлы разбираются командой `npm run inspect` — см. следующий шаг.

### 2. Разобрать, что нападало в `captures/`

```bash
npm run inspect
```

Ранжирует все захваченные ответы по тому, насколько они похожи на данные о
матчах:

```
matches  team-like  size     file              url
      1          1      247  0001-xhr.json     https://gg.bet/api/live/events
      0          2      135  0002-ws.json      wss://gg.bet/socket
      0          0       55  0003-xhr.json     https://gg.bet/api/banners
```

- `matches` — сколько матчей вытащил парсер. Больше нуля — всё работает.
- `team-like` — сколько мест в JSON похожи на «две стороны матча». Ненулевое
  значение при `matches: 0` означает: данные здесь есть, но парсер не узнал
  структуру.

Дальше смотрим конкретный файл:

```bash
node src/inspect.mjs 0002-ws.json
```

Печатает, где именно лежат команды, и **скелет** payload'а — значения заменены
образцами, массивы схлопнуты до первого элемента. Из 200 КБ получается пара
десятков читаемых строк, которые не стыдно вставить в чат или issue.

### 3. Watch — живая таблица и история

```bash
npm run watch
```

Печатает обновляемую сводку:

```
gg.bet · CS2 live · 21:14:03
========================================================================

NAVI vs FaZe  13:9
  ESL Pro League
    Winner NAVI                    1.72
  ^ Winner FaZe                    2.05
```

`^` / `v` — движение коэффициента с прошлой отрисовки.

Параллельно всё пишется в `odds-history.csv` — по строке на **каждое изменение**
коэффициента, а не на каждый тик:

```csv
ts,match_id,team_a,team_b,score,market,selection,price
2026-08-23T18:14:03.221Z,evt-991,NAVI,FaZe,13:9,Winner,FaZe,2.05
```

Этого достаточно, чтобы потом построить движение линии по любому матчу.

## Флаги

| Флаг | Назначение |
|---|---|
| `--discover` | режим захвата сырых payload'ов |
| `--url <url>` | другая страница (по умолчанию — лайв CS) |
| `--interval <sec>` | период перерисовки, по умолчанию 10 |
| `--out <file>` | файл истории, по умолчанию `odds-history.csv` |
| `--proxy <server>` | `http://user:pass@host:port` |
| `--headful` | показать окно браузера |

## Структура

| Файл | Что делает |
|---|---|
| `src/monitor.mjs` | браузер, перехват трафика, вывод, CSV |
| `src/extract.mjs` | эвристический разбор payload'а в матчи и коэффициенты |
| `src/inspect.mjs` | разбор захваченных payload'ов: рейтинг и скелет |
| `src/extract.test.mjs` | тесты парсера: `npm test` |

## Как работает парсер

`extract.mjs` не завязан на конкретные имена полей. Он обходит JSON и считает
объект матчем, если в нём есть **две именованные стороны** (ключи вида
`home`/`away`/`team`/`competitor`, либо массив из двух элементов) **и хотя бы
одна цена** (`odd`/`price`/`coef`/`rate` с числом в диапазоне 1.01–1000).
Счёт ищется по ключам `score`/`result`/`rounds`/`maps`.

Из-за этого он переживает переименование полей, но может ошибаться на
непривычной структуре — для этого и нужен `--discover`.

## Оговорка

Автоматический сбор котировок обычно противоречит пользовательскому соглашению
букмекера. Проверьте условия gg.bet перед регулярным использованием.
